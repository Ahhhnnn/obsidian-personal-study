# s07: 任务系统 - 持久化任务图与依赖管理

> *"大目标要拆成小任务，排好序，记在磁盘上"* -- 文件持久化的任务图，为多 agent 协作打基础。

## 问题背景

### s03 TodoManager 的局限

s03 的 TodoManager 只是内存中的扁平清单：
- 没有执行顺序
- 没有依赖关系
- 状态只有"做完/没做完"
- **上下文压缩后丢失**

### 真实任务的结构

```
大目标：重构编译器
    ├─ 任务 A：解析器重构
    ├─ 任务 B：AST 转换（依赖 A）
    ├─ 任务 C：代码生成（依赖 B）
    ├─ 任务 D：类型检查（依赖 A，与 B 并行）
    └─ 任务 E：测试验证（依赖 C、D）
```

没有显式的关系，智能体分不清：
- 什么可以做？
- 什么被卡住？
- 什么能同时跑？

## 解决方案：持久化任务图

### 核心思想

> **"在对话外部的状态能在压缩后存活"**

把扁平清单升级为**持久化到磁盘的任务图**。每个任务是一个 JSON 文件，有状态、前置依赖 (`blockedBy`) 和后置依赖 (`blocks`)。

### 任务图结构

```
.tasks/
  task_1.json  {"id":1, "status":"completed", "subject":"解析器重构"}
  task_2.json  {"id":2, "blockedBy":[1], "status":"pending", "subject":"AST 转换"}
  task_3.json  {"id":3, "blockedBy":[1], "status":"pending", "subject":"类型检查"}
  task_4.json  {"id":4, "blockedBy":[2,3], "status":"pending", "subject":"代码生成"}
  task_5.json  {"id":5, "blockedBy":[4], "status":"pending", "subject":"测试验证"}
```

### 可视化依赖图 (DAG)

```
                 +----------+
            +--> | task 2   | --+
            |    | AST 转换 |   |
+----------+     +----------+    +--> +----------+
| task 1   |                          | task 4   |
| 解析器   | --> +----------+    +--> | 代码生成 |
| completed|     | task 3   | --+     +----------+
+----------+     | 类型检查 |          |
                 +----------+          v
                                       +----------+
                                       | task 5   |
                                       | 测试验证 |
                                       +----------+

顺序:   task 1 必须先完成
并行:   task 2 和 3 可以同时执行
依赖:   task 4 要等 2 和 3 都完成
状态:   pending -> in_progress -> completed
```

## TaskManager 实现

### 核心类结构

```python
class TaskManager:
    def __init__(self, tasks_dir: Path):
        self.dir = tasks_dir
        self.dir.mkdir(exist_ok=True)
        self._next_id = self._max_id() + 1  # 自增 ID

    def _max_id(self) -> int:
        """扫描目录获取最大 ID"""
        ids = [int(f.stem.split("_")[1]) for f in self.dir.glob("task_*.json")]
        return max(ids) if ids else 0
```

### CRUD 操作

#### Create

```python
def create(self, subject: str, description: str = "") -> str:
    task = {
        "id": self._next_id,
        "subject": subject,
        "description": description,
        "status": "pending",      # pending / in_progress / completed
        "blockedBy": [],          # 前置依赖
        "blocks": [],             # 后置依赖
        "owner": "",              # 任务所有者（s09+ 使用）
    }
    self._save(task)
    self._next_id += 1
    return json.dumps(task, indent=2)
```

#### Update

```python
def update(self, task_id: int, status: str = None,
           add_blocked_by: list = None, add_blocks: list = None) -> str:
    task = self._load(task_id)

    if status:
        if status not in ("pending", "in_progress", "completed"):
            raise ValueError(f"Invalid status: {status}")
        task["status"] = status
        # 完成任务时，自动解锁依赖它的任务
        if status == "completed":
            self._clear_dependency(task_id)

    if add_blocked_by:
        task["blockedBy"] = list(set(task["blockedBy"] + add_blocked_by))

    if add_blocks:
        task["blocks"] = list(set(task["blocks"] + add_blocks))
        # 双向更新：被阻塞任务的 blockedBy 也要添加自己
        for blocked_id in add_blocks:
            blocked = self._load(blocked_id)
            if task_id not in blocked["blockedBy"]:
                blocked["blockedBy"].append(task_id)
                self._save(blocked)

    self._save(task)
    return json.dumps(task, indent=2)
```

### 依赖解除机制-重要

```python
def _clear_dependency(self, completed_id: int):
    """从所有其他任务的 blockedBy 列表中移除完成的任务"""
    for f in self.dir.glob("task_*.json"):
        task = json.loads(f.read_text())
        if completed_id in task.get("blockedBy", []):
            task["blockedBy"].remove(completed_id)
            self._save(task)
```

**关键点**：完成任务时自动解锁后续任务，无需手动管理。

### 任务列表渲染

```python
def list_all(self) -> str:
    tasks = []
    for f in sorted(self.dir.glob("task_*.json")):
        tasks.append(json.loads(f.read_text()))

    if not tasks:
        return "No tasks."

    lines = []
    for t in tasks:
        marker = {
            "pending": "[ ]",
            "in_progress": "[>]",
            "completed": "[x]"
        }.get(t["status"], "[?]")

        blocked = f" (blocked by: {t['blockedBy']})" if t.get("blockedBy") else ""
        lines.append(f"{marker} #{t['id']}: {t['subject']}{blocked}")

    return "\n".join(lines)
```

**输出示例**：
```
[x] #1: 解析器重构
[>] #2: AST 转换
[ ] #3: 类型检查
[ ] #4: 代码生成 (blocked by: [2, 3])
[ ] #5: 测试验证 (blocked by: [4])
```

## 与 s03 Todo 的对比

| 特性 | s03 Todo | s07 Tasks |
|-----|----------|-----------|
| **存储** | 内存（messages 列表） | 磁盘（JSON 文件） |
| **压缩后** | ❌ 丢失 | ✅ 保留 |
| **依赖关系** | 无 | 双向依赖图 (`blockedBy`/`blocks`) |
| **状态追踪** | 扁平 | `pending` → `in_progress` → `completed` |
| **多代理** | 无法共享 | 可共享（同文件系统） |
| **复杂度** | 简单 | 中等 |
| **适用场景** | 单次会话快速清单 | 多步复杂任务 |

## 会话隔离问题分析

### 当前实现的问题

```python
# 全局共享目录
TASKS_DIR = WORKDIR / ".tasks"

# 会话 A
用户 A: "创建任务：修复登录 bug"
    ↓
.tasks/task_1.json {"subject": "修复登录 bug", ...}

# 会话 B（稍后启动）
用户 B: "创建任务：添加支付功能"
    ↓
.tasks/task_2.json {"subject": "添加支付功能", ...}

# 会话 B 调用 task_list()
[ ] #1: 修复登录 bug        ← 会话 A 的任务！
[>] #2: 添加支付功能
```

### 导致的问题

| 问题 | 影响 |
|-----|------|
| **任务混淆** | 新会话看到旧会话的任务 |
| **ID 冲突** | `_max_id()` 跨会话递增，不会重置 |
| **状态污染** | 旧任务的 `blockedBy` 可能影响新任务 |
| **清理困难** | 无法区分哪些任务属于哪个会话 |

### 解决方案对比

#### 方案 1：会话 ID 隔离（推荐）

```python
import uuid

class SessionTaskManager:
    def __init__(self, tasks_dir: Path):
        self.session_id = str(uuid.uuid4())[:8]
        self.dir = tasks_dir / self.session_id
        self.dir.mkdir(parents=True, exist_ok=True)
        self._next_id = 1  # 每个会话从 1 开始
```

**目录结构**：
```
.tasks/
  a3f7c21e/          # 会话 A
    task_1.json
    task_2.json
  9b4d8f12/          # 会话 B
    task_1.json
    task_2.json
```

**优点**：完全隔离，清理简单（删除整个会话目录）

#### 方案 2：任务带会话标签

```python
def create(self, subject: str, description: str, session_id: str) -> str:
    task = {
        "id": self._next_id,
        "subject": subject,
        "session_id": session_id,  # 会话标记
        ...
    }

def list_all(self, session_id: str = None) -> str:
    # 只返回指定会话的任务
```

**优点**：灵活性高，支持跨会话查询

#### 方案 3：时间戳目录

```python
from datetime import datetime

session_dir = datetime.now().strftime("%Y%m%d_%H%M%S")
self.dir = tasks_dir / session_dir
```

**优点**：自然排序，易于查找历史

### 推荐策略

| 场景 | 推荐方案 |
|-----|---------|
| 单用户，同时一个会话 | 方案 1（会话 ID） |
| 需要历史记录追溯 | 方案 2（任务标签） |
| 多用户并发 | 方案 1 + 权限控制 |
| 简单实现 | 方案 3（时间戳） |

## 核心洞察

### 1. 持久化超越上下文

> **"状态在对话外部就能在压缩后存活"**

任务存储在磁盘的 JSON 文件中，完全独立于对话上下文。即使上下文被压缩成摘要，任务状态依然保留。

### 2. 依赖图显式化协调

```
三个核心问题：
- 什么可以做？    → pending 且 blockedBy 为空
- 什么被卡住？    → blockedBy 不为空
- 什么做完了？    → status = completed
```

### 3. 为多代理协作打基础

任务图是 s07 之后所有机制的**协调骨架**：
- s08 后台执行
- s09-s11 多 agent 团队
- s12 worktree 隔离

都读写同一个任务图结构。

## 总结

### 任务图的价值

| 维度 | 价值 |
|-----|------|
| **结构化** | DAG 表达复杂依赖关系 |
| **持久化** | 压缩和重启后存活 |
| **协调性** | 为多代理协作提供基础 |
| **可观测** | 随时查看整体进度 |

### 设计权衡

| 选择 | 理由 |
|-----|------|
| 文件系统而非数据库 | 简单、可观测、易于调试 |
| 双向依赖 (`blockedBy`/`blocks`) | 快速查询，避免图遍历 |
| 自动解锁依赖 | 减少手动操作，降低出错 |

### 使用建议

- **简单任务**：用 s03 Todo（内存清单）
- **复杂多步任务**：用 s07 Tasks（持久化图）
- **需要跨会话**：实现会话隔离机制
- **多代理协作**：基于任务图扩展

> **"最好的任务系统是你愿意用的系统"** -- 从简单开始，按需演进。
