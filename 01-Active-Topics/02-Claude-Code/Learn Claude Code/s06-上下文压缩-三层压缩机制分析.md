# s06: 上下文压缩 - 三层压缩机制深度分析

> *"上下文总会满，要有办法腾地方"* -- 三层压缩策略，换来无限会话

## 问题背景

上下文窗口是有限的。读一个 1000 行的文件就吃掉 ~4000 token；读 30 个文件、跑 20 条命令，轻松突破 100k token。不压缩，智能体根本没法在大项目里干活。

### Token 消耗示例

| 操作 | Token 消耗 |
|-----|-----------|
| 读取 1000 行代码 | ~4000 |
| 执行 10 条 bash 命令 | ~2000 |
| LLM 分析回复 | ~1000 |
| 30 个文件 + 20 条命令 | ~100k+ |

## 三层压缩架构

```
Every turn:
    +------------------+
    | 工具调用结果      |
    +------------------+
            |
            v
    [Layer 1: micro_compact]        (静默，每轮执行)
      将旧 tool_result 替换为占位符
      "[Previous: used {tool_name}]"
            |
            v
    [检查: tokens > 50000?]
       |               |
       否              是
       |               |
       v               v
    继续    [Layer 2: auto_compact]
              保存完整记录到 .transcripts/
              LLM 总结对话
              用 [summary] 替换所有消息
                    |
                    v
            [Layer 3: compact 工具]
              模型显式调用 compact
              与 auto_compact 相同的总结机制
```

## Layer 1: micro_compact - 静默压缩

### 核心逻辑

```python
def micro_compact(messages: list) -> list:
    # 1. 收集所有 tool_result
    tool_results = []
    for msg_idx, msg in enumerate(messages):
        if msg["role"] == "user" and isinstance(msg.get("content"), list):
            for part_idx, part in enumerate(msg["content"]):
                if isinstance(part, dict) and part.get("type") == "tool_result":
                    tool_results.append((msg_idx, part_idx, part))

    # 2. 如果只有最近 3 个，不处理
    if len(tool_results) <= KEEP_RECENT:  # 3
        return messages

    # 3. 找到每个 tool_result 对应的工具名
    tool_name_map = {}
    for msg in messages:
        if msg["role"] == "assistant":
            for block in msg.get("content", []):
                if hasattr(block, "type") and block.type == "tool_use":
                    tool_name_map[block.id] = block.name

    # 4. 清理旧结果（保留最近 3 个）
    to_clear = tool_results[:-KEEP_RECENT]
    for _, _, result in to_clear:
        if len(result.get("content", "")) > 100:
            tool_id = result.get("tool_use_id", "")
            tool_name = tool_name_map.get(tool_id, "unknown")
            result["content"] = f"[Previous: used {tool_name}]"

    return messages
```

### 压缩效果

```
压缩前：
Tool Result: file1.txt
               file2.txt
               file3.txt
               ... (5000 字符)

压缩后：
Tool Result: [Previous: used bash] (30 字符)
```

### 关键洞察

> **工具结果的原始内容不重要，重要的是 LLM 基于结果得出的结论。**

### 适用场景

| 适合 | 不适合 |
|-----|-------|
| 工具结果是中间数据 | 需要回溯原始数据 |
| LLM 已生成分析结论 | 需要对比多个工具结果 |
| 单次处理型任务 | 聚合分析型任务 |

## Layer 2: auto_compact - 自动总结

### 触发条件

```python
if estimate_tokens(messages) > THRESHOLD:  # 50000
    messages[:] = auto_compact(messages)
```

### 核心逻辑

```python
def auto_compact(messages: list) -> list:
    # 1. 保存完整记录到磁盘
    TRANSCRIPT_DIR.mkdir(exist_ok=True)
    transcript_path = TRANSCRIPT_DIR / f"transcript_{int(time.time())}.jsonl"
    with open(transcript_path, "w") as f:
        for msg in messages:
            f.write(json.dumps(msg, default=str) + "\n")

    # 2. 让 LLM 总结对话
    conversation_text = json.dumps(messages, default=str)[:80000]
    response = client.messages.create(
        model=MODEL,
        messages=[{"role": "user", "content":
            "Summarize this conversation for continuity. Include: "
            "1) What was accomplished, 2) Current state, 3) Key decisions made. "
            "Be concise but preserve critical details.\n\n" + conversation_text}],
        max_tokens=2000,
    )
    summary = response.content[0].text

    # 3. 用摘要替换所有消息
    return [
        {"role": "user", "content": f"[Conversation compressed. Transcript: {transcript_path}]\n\n{summary}"},
        {"role": "assistant", "content": "Understood. I have the context from the summary. Continuing."},
    ]
```

### 压缩效果

| 阶段 | Token 数 |
|-----|---------|
| 压缩前 | ~50000 |
| auto_compact | ~500 (LLM 摘要) |

### 关键点

- **信息不丢失**：完整记录保存在 `.transcripts/` 目录
- **原地修改**：使用 `messages[:]` 确保外部引用同步更新

## Layer 3: compact 工具 - 手动触发

```python
{"name": "compact", "description": "Trigger manual conversation compression."}
```

LLM 可以主动判断需要压缩时调用此工具。

## 关键问题分析：文件内容丢失问题

### 问题场景

```
用户: "分析所有 Python 文件，然后对比它们的设计模式"
    ↓
LLM: read_file("a.py") → 1000 行代码
    ↓
[ micro_compact 可能会压缩 ]
    ↓
LLM: read_file("b.py")
    ↓
LLM: read_file("c.py")
    ↓
LLM: "现在对比 A、B、C 的设计模式..."
    ❌ 问题：a.py 的原始内容可能已被压缩
```

### 根本原因

micro_compact 的设计假设：**工具结果是一次性消耗品**。但在聚合分析场景下，这个假设不成立。

### 解决方案对比

#### 方案 1：让 LLM 在读取时立即分析

```python
# 修改系统提示
SYSTEM = """
After reading each file, immediately document:
1. Key patterns used
2. Design choices
3. Notable features

Save this analysis in your response for later comparison.
"""
```

**优点**：分析内容保存在 LLM 回复中（不被压缩）
**缺点**：增加单次处理复杂度

#### 方案 2：使用子代理并行分析

```python
主代理：
  ├─ 子代理 1：分析 a.py → 返回报告
  ├─ 子代理 2：分析 b.py → 返回报告
  └─ 子代理 3：分析 c.py → 返回报告
       ↓
  主代理：对比三份报告
```

**优点**：
- 子代理返回分析报告而非原始代码
- 独立上下文，不污染主会话
- 适合并行处理

**缺点**：需要额外的代理协调

#### 方案 3：智能压缩（按工具类型）

```python
TOOL_KEEP_RESULT = {"read_file", "grep"}  # 需要保留结果

def micro_compact(messages: list) -> list:
    for _, _, result in to_clear:
        tool_name = tool_name_map.get(tool_id, "unknown")
        if tool_name not in TOOL_KEEP_RESULT:  # 检查
            result["content"] = f"[Previous: used {tool_name}]"
```

**优点**：细粒度控制
**缺点**：需要手动维护工具白名单

#### 方案 4：禁用 micro_compact

```python
# 只在真正需要时压缩
def agent_loop(messages: list):
    while True:
        # micro_compact(messages)  # 注释掉
        if estimate_tokens(messages) > THRESHOLD:
            messages[:] = auto_compact(messages)
```

**优点**：保留所有原始数据
**缺点**：上下文增长更快

### 推荐策略

| 场景 | 推荐方案 |
|-----|---------|
| 单文件处理 | 方案 1（立即分析） |
| 多文件聚合分析 | 方案 2（子代理） |
| 混合场景 | 方案 3（智能压缩） |
| 小项目 | 方案 4（禁用 micro） |

## 完整循环整合

```python
def agent_loop(messages: list):
    while True:
        # Layer 1: 每次调用前微压缩
        micro_compact(messages)

        # Layer 2: token 超限时自动压缩
        if estimate_tokens(messages) > THRESHOLD:
            messages[:] = auto_compact(messages)  # ← 注意 messages[:]

        response = client.messages.create(...)

        # ... 工具执行 ...

        # Layer 3: 手动压缩
        if manual_compact:
            messages[:] = auto_compact(messages)
```

### `messages[:]` 的重要性

```python
# ❌ 错误
messages = auto_compact(messages)
# 外部 history 引用不会被更新

# ✅ 正确
messages[:] = auto_compact(messages)
# 原地修改，外部引用同步更新
```

## 总结

### 三层压缩的本质

| 层级 | 触发时机 | 激进程度 | 适用场景 |
|-----|---------|---------|---------|
| Layer 1 (micro) | 每轮 | 低 | 日常维护 |
| Layer 2 (auto) | Token 超限 | 高 | 自动清理 |
| Layer 3 (manual) | LLM 判断 | 高 | 按需触发 |

### 核心原则

1. **信息不丢失**：完整记录保存到磁盘
2. **渐进式压缩**：从温和到激进
3. **LLM 驱动**：让智能体判断何时压缩
4. **场景适配**：根据任务调整压缩策略

### 关键洞察

> **"代理可以有策略地遗忘，并持续工作。"**

压缩不是丢失信息 —— 是把详细信息转移到磁盘，保留关键摘要在内存中。

> **"没有银弹。"**

micro_compact 不适合所有场景。理解任务特性，选择合适的压缩策略，才能构建高效的智能体。
