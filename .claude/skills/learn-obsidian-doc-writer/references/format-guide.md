# 文档格式参考

## 标题

```
# sXX: 主题 - 一句话副标题
```

- s 前缀 + 编号，用于系列文档排序
- 主题用中文，短横线连接
- 副标题一句话说清这节解决什么问题

## 引言

标题下面跟一句引用：

```
> *"用一句话概括这个机制的核心理念"*
```

一句话够了，不要写成段落。

## 问题背景

先说清楚"为什么要这个东西"：

- 当前遇到了什么问题
- 不解决会怎样
- 用数字说话（token 数、性能数据等）

格式示例：

```markdown
## 要解决的问题

s07 有了权限系统，工具执行前能做"允许/拒绝"。但很多需求不属于这条线：

- 会话开始时初始化环境
- 工具执行后写审计日志
```

用列表，不用散文叙述。

## 架构说明

用 ASCII 图，不用 Mermaid（Obsidian 渲染 Mermaid 需要插件，ASCII 随处可读）：

```markdown
## Hook 执行的完整链路

### subprocess 层面

每个 hook 定义最终走到 `subprocess.run`：

​```python
r = subprocess.run(
    hook_def["command"],
    shell=True,
    ...
)
​```
```

## 实现分析

拆成小节，每个小节讲一个具体机制：

- 先放代码片段（只截关键部分）
- 紧跟一两句说明这段代码做了什么
- 不解释显而易见的逻辑

## 问题分析

```markdown
## 几个容易忽略的点

**hook 挂了不阻塞主流程。** `try/except` 捕获异常和超时...

**多个 hook 按数组顺序执行。** 遇到退出码 1 后续...
```

每条加粗开头，一句话说结论，再展开。不超过 4 条。

## 变更对比

如果属于系列文档，放一个和上一版本的对比表：

```markdown
## 相对 s07 的变更

| 组件 | s07 | s08 |
|------|-----|-----|
| 主循环 | 内联权限检查 | + hook 接入点 |
```

只列变了的东西，不列没变的。

## 数据流

复杂流程用 ASCII 流程图 + 数据流示例：

```
模型生成 tool_use:
  name: "bash", input: {"command": "rm -rf /tmp/old"}
      |
      v
PreToolUse hook 执行:
  脚本检查目录，返回退出码 2, stderr="此目录下有重要文件"
      |
      v
主循环处理:
  results += tool_result("[Hook message]: 此目录下有重要文件")
```

用缩进表示层级，`|` 和 `v` 表示流向。
