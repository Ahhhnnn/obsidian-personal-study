# Learn Obsidian Doc Writer

根据技术资料生成结构清晰、去 AI 味的 Obsidian 学习文档。

## 工作流程

### 1. 收集资料

读取用户提供的所有输入：
- 源码文件路径 → 用 Read 工具读取
- 文档 URL → 用 WebFetch 或 defuddle 获取
- 直接粘贴的内容
- 用户口头描述的需求

如果用户提到参考某篇已有文档的格式，读那篇文档作为格式模板。

### 2. 确认输出位置

如果用户指定了路径，用用户的。

如果用户没指定路径，在 `/Users/hening/Documents/Obsidian Vault/` 下浏览目录结构，根据文档主题选择最合适的位置。不确定时问用户。

### 3. 起草文档

按 `references/format-guide.md` 中的格式模板组织内容。

起草原则：
- 直接说事，不铺垫
- 代码片段只放说明问题的部分，不放完整源码（完整源码读者可以自己去看）
- 用 ASCII 图解释架构，不用文字绕
- 表格用来说对比，不用来装显而易见的信息
- 每个章节解决一个具体问题

### 4. 去 AI 味

起草完成后，调用 `humanizer-zh` 技能对文档内容执行去 AI 味处理。不要自己手动自检，交给 humanizer-zh 按它的规则清单执行。

### 5. 交给用户 review

输出完整文档文本（不是文件），告诉用户"确认后写入文件"。等用户确认后再用 Write 工具写入。

如果用户说"直接写"或"不用 review"，跳过这步直接写入。

## 禁止事项

- 不写 README 式的"概述""目标读者""前置知识"开头
- 不在末尾加"总结""写在最后"的感悟段落
- 不用 emoji
- 不重复源码中已经有的完整代码，只截取关键片段
